## Context

PKB-002(Certification)/PKB-003(Education)과 같은 Phase(ADR-0020)에서
수상 정보를 구조적으로 저장한다. `Award`는 `CareerExperience`의 `type`으로
합치지 않고 독립 entity로 만든다(ADR-0018/ADR-0020). PKB-002/003과
독립적으로 구현 가능하며 서로 선후 의존이 없다.

## Scope

`Award` entity 신설, 기존 `career` 패키지에 CRUD API 추가.

### 1. 패키지 구조 (기존 `career` 패키지에 추가)

```
backend/src/main/java/com/careerops/backend/career/
├── (기존 CareerExperience*/Certification*/Education* 파일 — 무변경)
├── Award.java
├── AwardRepository.java
├── AwardService.java
├── AwardController.java
└── dto/
    ├── (기존 dto — 무변경)
    ├── AwardCreateRequest.java
    ├── AwardUpdateRequest.java
    ├── AwardResponse.java
    └── AwardListResponse.java
```

기존 `career` 패키지 파일들과 `job`/`collector`/`application` 패키지는
이번 Task에서 수정하지 않는다. PKB-002/003이 먼저 구현돼 있지 않아도 이
Task는 독립적으로 구현 가능하다.

### 2. Entity — `Award`

```java
@Entity
@Table(name = "career_awards")
public class Award {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private Long id;

    @Column(nullable = false, length = 200)
    private String title;

    @Column(length = 200)
    private String issuer;

    private LocalDate awardedDate;   // nullable

    @Column(length = 2000)
    private String description;

    @CreationTimestamp private Instant createdAt;
    @UpdateTimestamp private Instant updatedAt;
    ...
}
```

Lombok 없음, getter + 명시적 `updateX()` mutator, protected no-arg
생성자(`CareerExperience` 패턴). `title`만 `nullable = false`, 나머지
필드(날짜 포함)는 nullable — 문서 import/과거 기록 입력 시 정확한
수상일을 모르는 경우를 막지 않기 위함(ADR-0020). `category` 필드는
만들지 않는다 — 이번 Phase에 이 필드를 소비할 필터/매칭 로직이 없다
(사용자 결정). `CareerExperience`와의 FK는 만들지 않는다 — 독립 entity로
유지한다(ADR-0020, "수상 프로젝트와 CareerExperience 직접 연결"은 소비자
불확실로 보류). "이 프로젝트로 받은 상"이라는 서사는 `description` 자유
텍스트로 표현한다.

### 3. Migration — `V10__create_career_awards_table.sql`

```sql
CREATE TABLE career_awards (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    title VARCHAR(200) NOT NULL,
    issuer VARCHAR(200),
    awarded_date DATE,
    description VARCHAR(2000),
    created_at TIMESTAMP(6) WITH TIME ZONE NOT NULL,
    updated_at TIMESTAMP(6) WITH TIME ZONE NOT NULL
);
```

`career_` prefix + 복수형. UNIQUE 제약/추가 index는 만들지 않는다 —
같은 제목의 수상(예: 매년 반복되는 사내 우수상)처럼 정당한 중복이 있을
수 있어 PK만으로 충분(ADR-0020). PKB-002/003과 구현 순서가 바뀔 수
있으므로, Codex는 구현 시점에 `ls backend/src/main/resources/db/
migration/`으로 실제 최신 번호를 확인하고 그 다음 번호를 쓴다. 파일명의
"V10"은 참고용 예상치다.

### 4. Repository

```java
public interface AwardRepository extends JpaRepository<Award, Long> {
    @Query("SELECT a FROM Award a ORDER BY a.awardedDate DESC NULLS LAST")
    Page<Award> findAllOrderByAwardedDateDescNullsLast(Pageable pageable);
}
```

`JobPostingRepository`의 JPQL `NULLS LAST` 문법 재사용. filter 없음
(PKB-002/003과 동일 판단).

### 5. Service — `AwardService`

단일 row CRUD, 부모+자식 aggregate가 아니므로 **`@Transactional`을
붙이지 않는다**(ADR-0015/ADR-0020).

- `create()`: cross-field 검증 없음(날짜 필드가 `awardedDate` 하나뿐이라
  비교 대상이 없음) — `title` Bean Validation만으로 충분.
- `update()`(PATCH): 요청 필드가 `null`이면 무변경.
- `delete()`: 존재하지 않으면 404, 있으면 hard delete.
- `find(id)`: `repository.findById(id).orElseThrow(() -> new
  ResponseStatusException(HttpStatus.NOT_FOUND))`.

### 6. Controller

```
POST   /api/career/awards        -> 201, AwardResponse
GET    /api/career/awards        -> 200, AwardListResponse (pagination only)
GET    /api/career/awards/{id}   -> 200, AwardResponse / 404
PATCH  /api/career/awards/{id}   -> 200, AwardResponse / 404
DELETE /api/career/awards/{id}   -> 204 / 404
```

`GET` 목록은 `@PageableDefault(size = 20)` + size 100 clamp, 정렬은
`awardedDate DESC NULLS LAST` 서버 고정, filter 없음.

### 7. DTO

**`AwardCreateRequest`**:
```java
public record AwardCreateRequest(
        @NotBlank @Size(max = 200) String title,
        @Size(max = 200) String issuer,
        LocalDate awardedDate,
        @Size(max = 2000) String description) {}
```

**`AwardUpdateRequest`**: 위와 동일한 필드 전부 optional(`title`도
`@Size(max=200)`만, `@NotBlank` 제거).

**`AwardResponse`**: `id`/`title`/`issuer`/`awardedDate`/`description`/
`createdAt`/`updatedAt`(자식이 없으므로 단일 flat DTO).

**`AwardListResponse`**: `content: List<AwardResponse>`,
`totalElements`/`totalPages`/`page`/`size`.

### 8. custom metric

추가하지 않는다 — 일반 CRUD(APPLICATION-001/002, PKB-001/002/003과 동일
판단).

## Out of Scope

- `category` 필드 — 실제 소비처(필터/매칭)가 없다.
- `CareerExperience`와의 FK(우수상↔수상 프로젝트 연결) — 소비자 불확실로
  보류(ADR-0020). 필요성이 확인되면 별도 Task에서 additive migration.
- `sourceType`/`sourceReference`(provenance) — 문서 import Task 설계 시
  additive migration으로 추가한다.
- 제목/발급기관 검색 filter — 실제 소비자(UI) 없는 상태에서 미리 만들지
  않는다.
- 공용 tag 시스템 복제.
- AI/RAG/embedding/pgvector/semantic search, 적합도 점수, 자기소개서
  생성.
- PDF/DOCX import, OCR, LLM extraction.
- 사용자 인증/다중 사용자, Frontend, Calendar/알림.
