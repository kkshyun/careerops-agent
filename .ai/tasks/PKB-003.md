ADR-0020)에서 학력 정보를 구조적으로 저장한다. `Education`은

### 2. Entity — `Education`

```java
@Entity
@Table(name = "career_educations")
public class Education {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private Long id;

    @Column(nullable = false, length = 200)
    private String institution;

    @Column(length = 200)
    private String major;

    @Enumerated(EnumType.STRING)
    @Column(length = 50)
    private EducationDegree degree;    // nullable

    @Enumerated(EnumType.STRING)
    @Column(length = 50)
    private EducationStatus status;    // nullable

    private LocalDate startDate;   // nullable
    private LocalDate endDate;     // nullable

    @Column(precision = 5, scale = 2)
    private BigDecimal gpa;         // nullable

    @Column(name = "gpa_scale", precision = 5, scale = 2)
    private BigDecimal gpaScale;    // nullable

    @Column(length = 2000)
    private String description;

    @CreationTimestamp private Instant createdAt;
    @UpdateTimestamp private Instant updatedAt;
    ...
}
```

Lombok 없음, getter + 명시적 `updateX()` mutator, protected no-arg
생성자(`CareerExperience` 패턴). `institution`만 `nullable = false`,
나머지 전 필드(날짜/degree/status/gpa 포함)는 nullable — 문서 import/
과거 기록 입력 시 정확한 정보를 모르는 경우를 막지 않기 위함(ADR-0020).
이 프로젝트에서 `BigDecimal` 컬럼을 쓰는 최초 사례다(신규 dependency는
아님, JDK/Hibernate 표준 지원). `precision=5, scale=2`는 4.5 만점 척도와
100점 만점 척도(백분율 GPA) 모두 표현 가능(최대 999.99).

### 3. `EducationDegree` enum (신규, `EnumType.STRING`, nullable 컬럼)

public enum EducationDegree { HIGH_SCHOOL, ASSOCIATE, BACHELOR, MASTER, DOCTORATE, OTHER }

### 4. `EducationStatus` enum (신규, `EnumType.STRING`, nullable 컬럼)

```java
public enum EducationStatus { ENROLLED, ON_LEAVE, GRADUATED, EXPECTED_GRADUATION, WITHDRAWN }
```

두 enum 모두 `OTHER`/미지정(null) escape hatch를 허용한다 — 해외 학위나
특수 과정처럼 고정 enum이 못 담는 값, 혹은 아직 확정되지 않은 정보를
강제로 채우지 않기 위함(ADR-0020).

### 5. Migration — `V9__create_career_educations_table.sql`

```sql
CREATE TABLE career_educations (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    institution VARCHAR(200) NOT NULL,
    major VARCHAR(200),
    degree VARCHAR(50),
    status VARCHAR(50),
    start_date DATE,
    end_date DATE,
    gpa NUMERIC(5,2),
    gpa_scale NUMERIC(5,2),
    description VARCHAR(2000),
    created_at TIMESTAMP(6) WITH TIME ZONE NOT NULL,
    updated_at TIMESTAMP(6) WITH TIME ZONE NOT NULL
);
```

`career_` prefix + 복수형. UNIQUE 제약/추가 index는 만들지 않는다 —
같은 학교 재입학(학·석사 등) 같은 정당한 중복이 있을 수 있어 PK만으로
충분(ADR-0020). PKB-002가 먼저 적용되면 이 파일은 V9, 아직이면 실제
최신 버전을 확인해 다음 번호로 조정한다(PKB-002/003/004는 서로 독립
구현이라 실행 순서가 바뀔 수 있음 — Codex는 구현 시점의 실제 최신
migration 번호를 `ls backend/src/main/resources/db/migration/`로 확인
후 번호를 정한다).

### 7. Service — `EducationService`

단일 row CRUD, 부모+자식 aggregate가 아니므로 **`@Transactional`을
붙이지 않는다**(ADR-0015/ADR-0020).

- `create()`: cross-field 검증 후 저장.
  - `validateDates(startDate, endDate)`: 둘 다 있고 `endDate < startDate`면
    400(`CareerExperienceService.validateDates()` 패턴).
  - `validateGpa(gpa, gpaScale)`: **하나만 있으면 400**("gpa와 gpaScale은
    함께 입력하거나 함께 생략해야 합니다"). 둘 다 있으면 `gpa < 0` 또는
    `gpaScale <= 0` 또는 `gpa > gpaScale`이면 400. 둘 다 없으면 통과
    (검증 스킵).
- `update()`(PATCH): 요청 필드가 `null`이면 무변경. cross-field 검증은
  병합된 값(요청값 없으면 기존값 유지) 기준으로 수행 — 예를 들어
  `description`만 PATCH해도 기존 `gpa`/`gpaScale` 조합이 유지되고,
  `gpa`만 새로 PATCH하면 기존 `gpaScale`과 병합해 재검증한다
  (`CareerExperienceService.update()`의 `start`/`end` 병합 패턴을
  `startDate`/`endDate`와 `gpa`/`gpaScale` 양쪽에 동일하게 적용).
- `delete()`: 존재하지 않으면 404, 있으면 hard delete.

## Technical Notes

- 기존 `job`/`collector`/`application` 패키지, `CareerExperience`/
  `Certification` 관련 파일은 이번 Task에서 수정하지 않는다.
- Entity/Repository/Service/Controller/DTO는 `CareerExperience`
  (`.ai/tasks/PKB-001.md`) 패턴을 재사용하되 **`@Transactional`은 붙이지
  않는다**(ADR-0020).
- `BigDecimal` 필드는 이 프로젝트 최초 사용처다 — JPA `@Column(precision,
  scale)`만으로 충분하며 신규 dependency는 없다. Jackson이 JSON 숫자를
  `BigDecimal`로 역직렬화할 때 정밀도가 유실되지 않는지(예: `3.80` →
  `3.8`이 아니라 `3.80` 유지 여부는 무관, 값의 동등성만 검증) 테스트로
  확인.
- migration 파일 번호(V8/V9/V10)는 PKB-002/004와 구현 순서가 바뀔 수
  있으므로, Codex는 구현 시점에 `ls backend/src/main/resources/db/
  migration/`으로 실제 최신 번호를 확인하고 그 다음 번호를 쓴다. 파일명의
  "V9"는 참고용 예상치다.
- validation cross-field 검증은 Service 내 수동 검증 +
  `ResponseStatusException(BAD_REQUEST, msg)` 패턴 재사용
  (`@ControllerAdvice`/`@AssertTrue` 등 새 메커니즘 도입 금지).
- 신규 production/test dependency 없음.
