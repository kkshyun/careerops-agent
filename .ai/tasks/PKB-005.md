## Context

PKB(`CareerExperience`/`Certification`/`Education`/`Award`, PKB-001~004)는
지금까지 사람이 API로 직접 입력한 데이터만 저장해왔다. 이제 "사용자가
가진 문서(이력서/포트폴리오 등) 원문 → 검토 → PKB 반영"이라는 import
파이프라인을 시작한다. AGENTS.md의 핵심 제약(AI가 사용자가 하지 않은
경험/수치를 만들어내지 못하게 막는 근거 기반 검증 구조)에 따라, 이
파이프라인은 어떤 단계에서도 검토 없이 곧바로 PKB의 확정 사실로 저장하는
경로를 가져서는 안 된다(ADR-0021).

설계 검토 결과 이 목표는 한 Task로 다루기엔 범위가 넓어 **PKB-005/PKB-006로
순차 분리**하기로 사용자 승인을 받았다(ADR-0021):

- **PKB-005(이번 Task)**: 문서 출처(provenance)를 등록하는 기반만 만든다.
  사용자가 문서 원문 텍스트를 직접 붙여넣어 `SourceDocument`로 등록하고,
  그 문서에 대한 검토 작업 단위인 `ImportBatch`를 연다.
- **PKB-006(다음 Task, 이번엔 만들지 않음)**: `ImportCandidate`(검토
  대상 후보)와 검토/승인/거부 흐름, 그리고 승인 시 기존
  `CareerExperience`/`Certification`/`Education`/`Award` entity에
  provenance 컬럼(`sourceType`/`sourceImportCandidateId`)을 추가해
  실제로 PKB에 반영하는 로직을 다룬다.
- **PKB-007/008(후속 후보, 로드맵에만 남김)**: 파일 업로드(multipart)+
  PDF/DOCX 텍스트 추출, LLM 기반 구조화 추출. 이번 Phase에서 다루지
  않는다.

## Scope

신규 top-level 패키지 `com.careerops.backend.pkbimport`에 `SourceDocument`/
`ImportBatch` entity + CRUD(생성/목록/단건 조회만, 수정 없음) API를 만든다.

기존 `com.careerops.backend.manualimport`(IMPORT-001, 채용공고 URL 수동
등록)와는 이름이 겹치지 않는 완전히 다른 패키지다 — 혼동 방지를 위해
Codex는 `manualimport` 패키지를 절대 참고/수정하지 않는다.

### 2. Entity — `SourceDocument`

```java
@Entity
@Table(name = "source_documents")
public class SourceDocument {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private Long id;

    @Column(name = "file_name", length = 255)
    private String fileName;   // nullable — 사용자가 붙인 라벨일 뿐, 신뢰 불가

    @Enumerated(EnumType.STRING)
    @Column(name = "document_type", nullable = false, length = 50)
    private DocumentType documentType;

    @Column(name = "content_hash", nullable = false, length = 64)
    private String contentHash;   // rawText의 SHA-256, hex 인코딩(64자), 서버 계산

    @Column(name = "raw_text", nullable = false, length = 50000)
    private String rawText;

    @CreationTimestamp private Instant createdAt;
    ...
}
```

Lombok 없음, getter + protected no-arg 생성자(기존 컨벤션). `updatedAt`은
만들지 않는다 — 이번 Task에 수정(PATCH) API가 없다(`ExperienceTag`와 동일
판단, 자식이 아니라 "수정 API가 없는 entity"라는 공통점으로 재사용).
`fileName`은 nullable(사용자가 원문만 붙여넣고 파일명을 안 줄 수도 있음).
`documentType`은 필수 — 값 선택 비용이 낮고, 나중에 PKB-008(LLM 추출)의
프롬프트가 문서 종류별로 달라질 때 실제로 소비될 필드다.

### 3. `DocumentType` enum (신규, `EnumType.STRING`)

```java
public enum DocumentType { RESUME, PORTFOLIO, EXPERIENCE_NOTE, COVER_LETTER, OTHER }
```

### 4. `contentHash` 계산

서버가 `rawText`로부터 SHA-256을 계산해 소문자 hex 문자열(64자)로 저장한다.
`java.security.MessageDigest.getInstance("SHA-256")`(JDK 표준, 신규
dependency 없음)를 사용한다. **DB UNIQUE 제약을 걸지 않는다** — 동일
`rawText`로 여러 번 등록하는 것을 막지 않는다(ADR-0021 결정 6). hash는
현재는 참고용 정보로만 저장하고, 실제 dedup 로직은 이번 범위 밖이다.

### 5. Entity — `ImportBatch`

```java
@Entity
@Table(name = "import_batches")
public class ImportBatch {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private Long id;

    @ManyToOne(optional = false, fetch = FetchType.LAZY)
    @JoinColumn(name = "source_document_id", nullable = false)
    private SourceDocument sourceDocument;

    @Enumerated(EnumType.STRING)
    @Column(nullable = false, length = 20)
    private ImportBatchStatus status;   // 생성 시 항상 OPEN

    @CreationTimestamp private Instant createdAt;

    private Instant completedAt;   // nullable, 이번 Task에서는 항상 null

    ...
}
```

`ExperienceBullet`/`RecruitmentStep`과 동일한
`@ManyToOne(optional=false, fetch=LAZY) @JoinColumn` 단방향 FK 패턴(같은
패키지 내부 관계이므로 이 컨벤션을 그대로 따른다 — `career`↔`pkbimport`
사이의 plain `Long` 컬럼 방식과는 다른 경우임에 주의, ADR-0021 결정 3 참고).

### 6. `ImportBatchStatus` enum (신규, `EnumType.STRING`)

```java
public enum ImportBatchStatus { OPEN, COMPLETED }
```

**이번 Task에서는 `OPEN`만 실제로 생성된다.** `COMPLETED`는 PKB-006에서
"이 batch의 모든 candidate가 검토 완료됨"을 표시하기 위해 예약해 둔
값이다(`EnumType.STRING`+`VARCHAR` 컬럼이라 나중에 이 값을 실제로
쓰기 시작해도 마이그레이션이 필요 없다 — 이 프로젝트 전체가 네이티브
Postgres enum 대신 이 방식을 쓰는 이유와 동일). 이번 Task는 `status`를
바꾸는 어떤 API도 만들지 않는다(PATCH 없음).

### 7. Migration

**`V11__create_source_documents_table.sql`**:
```sql
CREATE TABLE source_documents (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    file_name VARCHAR(255),
    document_type VARCHAR(50) NOT NULL,
    content_hash VARCHAR(64) NOT NULL,
    raw_text VARCHAR(50000) NOT NULL,
    created_at TIMESTAMP(6) WITH TIME ZONE NOT NULL
);
```

**`V12__create_import_batches_table.sql`**:
```sql
CREATE TABLE import_batches (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    source_document_id BIGINT NOT NULL REFERENCES source_documents(id),
    status VARCHAR(20) NOT NULL,
    created_at TIMESTAMP(6) WITH TIME ZONE NOT NULL,
    completed_at TIMESTAMP(6) WITH TIME ZONE
);
```

`source_document_id` FK는 `ON DELETE` 절 없음(Postgres 기본 `NO ACTION`)
— `JobPosting`→`JobApplication`(ADR-0016)과 같은 기본 컨벤션. 현재
`SourceDocument` 삭제 API 자체가 없어 당장 실행 경로는 없지만, 향후
삭제 API가 추가될 때 조용히 잘못된 기본값이 들어가지 않도록 지금
명시적으로 결정해둔다. `content_hash`/`document_type`에 UNIQUE나 별도
index는 만들지 않는다(dedup 미강제, 실제 소비자가 아직 없는 조회 패턴에
대한 index 선투자 금지 — 기존 전체 컨벤션과 동일). Codex는 구현 시점에
`ls backend/src/main/resources/db/migration/`으로 실제 최신 번호를
확인하고(V11이 이미 다른 이유로 선점됐다면) 그 다음 번호를 쓴다. 파일명의
"V11"/"V12"는 참고용 예상치다.

### 8. Repository

```java
public interface SourceDocumentRepository extends JpaRepository<SourceDocument, Long> {
    @Query("SELECT d FROM SourceDocument d " +
           "WHERE (:documentType IS NULL OR d.documentType = :documentType) " +
           "ORDER BY d.createdAt DESC")
    Page<SourceDocument> search(@Param("documentType") DocumentType documentType, Pageable pageable);
}
```

```java
public interface ImportBatchRepository extends JpaRepository<ImportBatch, Long> {
    @Query("SELECT b FROM ImportBatch b " +
           "WHERE (:sourceDocumentId IS NULL OR b.sourceDocument.id = :sourceDocumentId) " +
           "ORDER BY b.createdAt DESC")
    Page<ImportBatch> search(@Param("sourceDocumentId") Long sourceDocumentId, Pageable pageable);
}
```

두 쿼리 모두 파라미터가 매핑된 컬럼과 **직접** 비교되므로(함수 인자
위치가 아님) FIX-001의 null-parameter typing 버그가 적용되지 않는다 —
`CareerExperienceRepository.search()`의 기존 `e.type = :type` 부분과
동일한, 이미 검증된 안전한 패턴이다. `LIKE`/`LOWER`/`CONCAT`을 쓰는
자유 텍스트 검색은 이번 Task에 없다.

### 9. Service

`SourceDocumentService`/`ImportBatchService` 모두 단일 row CRUD이므로
**`@Transactional`을 붙이지 않는다**(ADR-0015/0020과 동일 판단 — 부모+자식
다중 row 원자적 쓰기가 아님).

- `SourceDocumentService.create()`: `contentHash` 계산 → 저장 → 응답.
- `SourceDocumentService.findAll(documentType, pageable)`: `repository.search()`.
- `SourceDocumentService.findById(id)`: 없으면 404.
- `ImportBatchService.create(sourceDocumentId)`: `sourceDocumentRepository.findById()`로
  문서 존재 확인(없으면 404) → `status=OPEN`으로 `ImportBatch` 저장.
- `ImportBatchService.findAll(sourceDocumentId, pageable)`: `repository.search()`.
- `ImportBatchService.findById(id)`: 없으면 404.

## Out of Scope

- **`ImportCandidate` entity, 후보 검토/승인/거부 API** — PKB-006에서
  다룬다.
- **`career_experiences`/`career_certifications`/`career_educations`/
  `career_awards`에 `sourceType`/`sourceImportCandidateId` 컬럼 추가** —
  PKB-006의 additive migration으로 추가한다. 이번 Task는 `career`
  패키지를 전혀 수정하지 않는다.
- **파일 업로드(multipart/form-data, `MultipartFile`)** — `rawText`는
  JSON body 필드로 사용자가 직접 붙여넣는다. 파일 업로드는 PKB-007
  후보(로드맵에만 존재, 이번 Task 아님).
- **PDF/DOCX 텍스트 추출(Apache PDFBox/POI/Tika 등)** — PKB-007 후보.
  이번 Task는 어떤 문서 파싱 라이브러리도 추가하지 않는다.
- **LLM 기반 구조화 추출** — PKB-008 후보. 이번 Task는 AI/LLM client
  dependency를 추가하지 않는다.
- **`SourceDocument`/`ImportBatch` 수정(PATCH)/삭제(DELETE) API** — 이번
  Task는 생성/조회만 지원한다.
- **`contentHash` 기반 dedup 강제(UNIQUE 등)** — 참고용 정보로만
  저장한다(ADR-0021).
- **`rawText`에서 이메일/전화번호 등 개인정보를 파싱/추출하는 어떤
  로직도 포함하지 않는다** — `rawText`는 불투명한 텍스트 blob으로만
  저장한다.
- **`ImportBatch.status`를 `COMPLETED`로 전이시키는 API** — PKB-006에서
  candidate 검토 완료와 연결해 추가한다.
- 사용자 인증/다중 사용자, Frontend, Calendar/알림, embedding/pgvector/
  semantic search, 매칭/추천, 자기소개서 생성.

## Technical Notes

- 신규 패키지는 `com.careerops.backend.pkbimport`다 — 기존
  `com.careerops.backend.manualimport`(IMPORT-001, 채용공고 URL 수동
  등록)와 이름이 유사하지만 완전히 다른 도메인이니 혼동하지 말 것. 두
  패키지 다 이번 Task에서 서로 참조하지 않는다.
- `contentHash`는 `java.security.MessageDigest.getInstance("SHA-256")`
  (JDK 표준)으로 계산한다. 신규 production dependency 없음.
- `ImportBatch`는 같은 `pkbimport` 패키지 내부 관계이므로
  `ExperienceBullet`/`RecruitmentStep`과 동일한
  `@ManyToOne(optional=false, fetch=LAZY) @JoinColumn` 패턴을 쓴다 —
  이는 PKB-006에서 `career` 패키지 entity에 추가될 plain `Long` FK
  컬럼 방식(패키지 간 단방향 의존 유지 목적, ADR-0021)과는 다른 결정임에
  주의. 헷갈리지 않게 이 Task 범위(`pkbimport` 패키지 내부)에서는 기존
  `@ManyToOne` 컨벤션을 그대로 따른다.
- `SourceDocumentRepository.search()`/`ImportBatchRepository.search()`는
  파라미터가 매핑된 컬럼과 직접 비교되는 형태만 쓴다(FIX-001 재발 방지
  — `LIKE`/`LOWER`/`CONCAT` 함수 인자 위치에 파라미터를 두지 않는다).
- `ImportBatchStatus.COMPLETED`는 이번 Task에서 어떤 코드 경로도 생성하지
  않는 예약값이다 — Codex는 이 값을 실제로 세팅하는 로직을 추가하지
  않는다(PKB-006에서 추가됨).
- 신규 production/test dependency 없음.
